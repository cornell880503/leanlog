# 薄肌訓練記錄網頁：實作計畫

## 1. 目標

做一個**只給你自己用、手機優先**的訓練記錄網頁，可以加到手機主畫面，打開就像 App。**所有日常記錄都用點選和下拉選單完成，不需要打字。**資料存在雲端資料庫，我（Manus）可以直接讀取做分析和給建議。

已知的背景與設定：

| 項目 | 內容 |
|---|---|
| 身體 | 27 歲男生、179 cm、空腹體重 70–71 kg |
| 薄肌目標 | 體脂 10–12%、FFMI 19.5–21（去脂體重 ≥ 62.5 kg），以同一台 Boditrax 追蹤 |
| 基準掃描 2026-08-02 | 體重 68.6 kg、脂肪 9.5 kg、去脂體重 59.1 kg、肌肉 56.0 kg、內臟脂肪 5；分段數據全部匯入 |
| 摸高目標 | 助跑摸高 320 cm，目前約 305 cm（剛好摸到籃框） |
| 站立摸高 | 沒測過，用一般人的比例估算：身高 × 1.33 ≈ **238 cm**（可在設定裡修改）→ 目前助跑跳約 **67 cm**，目標約 **82 cm** |
| 訓練節奏 | 腿 → 背 → 胸 → 休，練三休一；有打球就多休一天 |
| 排球 | 不固定，一週最多一天，在週末 |

## 2. 畫面與使用流程

下方分頁列：**今天｜身體｜進度｜歷史**（右上角齒輪進設定）。

### 2.1 今天（首頁）

- 依照循環自動顯示**「今天建議：背日」**（或「休息」）。規則：看最後一次重訓是哪一天，照 腿 → 背 → 胸 → 休 往下排；如果最後一次重訓之後有打排球，就多排一天休息
- 大按鈕：**腿日／背日／胸日／排球／其他**，點一下直接開始
- **腿日提醒**：星期五、六選腿日時跳出提示「如果明天要打球，建議今天不要練腿（會影響跳躍，也增加膝蓋負擔），可以跟背日或胸日對調」，可以選「照樣練」或「換成背日／胸日」
- 本週小摘要：已練幾次、各肌群組數是否達標的小圓點、跳躍次數

### 2.2 重訓記錄（腿日／背日／胸日／其他）

- 開始時**自動帶入上一次同一個訓練日的動作、組數、重量、次數**，大部分時候只要逐組打勾
- 每個動作卡片：
  - 按鈕：**照上次**、**全部 +2.5 kg**、**全部 −2.5 kg**、**+1 組**、**−1 組**（加減的級距依器材而定：槓鈴 2.5、啞鈴 2、器械／纜繩 2.5、徒手負重 2.5）
  - 每一組：重量（下拉選單，依器材級距）、次數（下拉 1–30）、RPE 快速鈕（6／7／8／9／10，預設沿用上次）、熱身組開關、完成打勾
  - 卡片上會顯示上次的最佳組和 e1RM（推估 1RM）
- **新增動作**：從動作庫挑，可以用「本日常用／全部」分頁和肌群篩選，也有搜尋（搜尋要打字，但只是選填）
- **自訂動作**：動作庫裡沒有的話，可以新增，名稱、主要肌群、次要肌群、器材類型都用選的
- **換動作週期**：直接移除舊動作、加入新動作；下次同一天會自動帶入新的組合
- **結束訓練**：訓練時長自動計算（從開始到結束，也可以用下拉修改）；自評整體強度 sRPE 用 1–10 快速鈕選（附文字說明，例如「7＝很累但還行」）
- 結束後顯示摘要：總容量、各肌群有效組數、**新紀錄（PR）**、每個動作跟上次比較
- **中途不怕掉**：記錄過程即時存在手機（localStorage），重新整理或切換 App 都不會遺失，按結束才上傳

### 2.3 排球記錄

全部用點選：

- 類型：練習／比賽／休閒
- 時長：60／90／120／150／180 分鐘
- 強度：輕鬆（4）／普通（6）／累（7）／很累（9）
- 跳躍量：少（約 40 下）／中（約 80）／多（約 120）／很多（約 160）
- 膝蓋狀況：沒事／有點緊／會痛

### 2.4 身體

- **體重**：大數字顯示，預設帶入上次數值，用 ±0.1、±0.5 按鈕調整，另有「空腹」開關
- **摸高測試**：助跑摸高用下拉選單（280–340 cm）；站立摸高沿用設定值
- **Boditrax 掃描**：數字表單，全部欄位預設帶入上次的值，只要改有變動的；也可以直接把照片傳給 Manus，由我代為輸入

### 2.5 進度（儀表板）

| 卡片 | 內容 |
|---|---|
| 薄肌 | 身體組成地圖（X 軸體脂率、Y 軸 FFMI，標出目標區和每次掃描的軌跡）、體脂與去脂體重進度條、還差多少、里程碑 M1／M2／最終 |
| 摸高 | 305 → 320 cm 進度、推估跳躍高度、歷次測試曲線 |
| 本週訓練 | 各肌群有效組數對照目標範圍的長條圖（本週進行中會另外標示）、訓練負荷、跳躍次數，以及**負荷暴增提醒**（超過前 3 週平均的 1.3 倍） |
| 力量趨勢 | 下拉選一個動作，顯示 e1RM 曲線 |
| 體重 | 每日體重加 7 日平均線 |

### 2.6 歷史

- 依日期列出每一次訓練；點進去可以看詳細內容、修改或刪除

### 2.7 設定

- 站立摸高（預設 238，估算值）、目標值（體脂、FFMI、摸高）、每週組數目標、訓練循環順序
- **匯出 CSV**（備份用）

## 3. 計算規則（和目前的分析程式一致）

| 項目 | 規則 |
|---|---|
| 容量 | 有效負重 × 次數；徒手動作的有效負重 = 當天體重 × 係數 + 額外負重（引體向上 1.0、雙槓 0.9、伏地挺身 0.65 等） |
| e1RM | Epley 公式：重量 × (1 + 次數 ÷ 30)，只算 12 下以內的正式組 |
| 有效組 | 非熱身、RPE ≥ 7（沒填 RPE 視為有效）的重訓組；主要肌群算 1 組、次要肌群算 0.5 組；增強式跳躍和爆發力動作不算進肌肥大組數 |
| 跳躍次數 | 排球的估計跳躍次數，加上增強式動作的次數 |
| 訓練負荷 | 時長（分鐘）× sRPE |
| 每週目標 | 胸 10–16、背 12–18、肩 10–16、二頭 8–14、三頭 8–14、核心 6–10、股四頭 6–10、腿後 6–10、臀 6–10、小腿 0–8 |
| 體組成 | 體脂率 = 脂肪 ÷ 體重；FFMI = 去脂體重 ÷ 身高²；達標＝連續兩次掃描都落在目標區 |
| 里程碑 | M1：2026-12-31 前去脂 ≥ 60.5 kg 且體脂 ≤ 13.5%；M2：2027-03-31 前 ≥ 61.5 kg 且 ≤ 12.5%；最終：2027-07-31 前 ≥ 62.5 kg 且 ≤ 12.0% |

## 5. 技術架構

### 5.1 技術組合

沿用已建立的專案範本：React + Tailwind 前端、Express + tRPC 後端、Drizzle + 平台提供的 MySQL 資料庫、Manus 帳號登入。圖表用範本裡已有的 recharts。

### 5.2 部署方式與快取

- **選擇**：用單一容器同時提供網頁檔案和 API（範本預設的 Dockerfile，健康檢查 `/api/health`）
- **理由**：每個畫面一打開就需要讀取你的私人資料，拆成「靜態前端＋另外的 API」對實際體感幫助不大，反而多一層路由設定。個人使用、流量很小，單一容器最單純
- **快取策略**：
  - `/assets/*`：檔名帶雜湊值，長期快取（`public, max-age=31536000, immutable`）
  - `index.html`：`no-cache`，確保改版後立刻拿到新版
  - `/api/*`：個人資料，`private, no-store`
- **已知取捨**：網站閒置一段時間後，第一次打開可能要等幾秒啟動，之後就正常

### 5.3 登入與權限

- Manus 帳號登入，登入一次後手機會保持登入（一年效期）
- 所有 API 都要求登入，所有資料都以登入者的帳號隔開

### 5.4 加到主畫面

- 建立專案專屬 logo，同時用在網站標頭、favicon、iOS 主畫面圖示（apple-touch-icon），並註冊為專案 logo
- 正式網址使用平台預設的 Web App Manifest，全螢幕開啟、不顯示瀏覽器列

### 5.5 資料表

| 資料表 | 主要欄位 |
|---|---|
| `sessions` | 使用者、日期、類型（腿／背／胸／排球／其他）、開始與結束時間、時長、sRPE、跳躍次數、排球類型、膝蓋狀況、備註 |
| `workout_sets` | 所屬訓練、動作代碼、動作順序、組序、重量、次數、RPE、是否熱身、當下體重 |
| `custom_exercises` | 使用者、名稱、適用訓練日、主要與次要肌群、器材、類型、體重係數 |
| `body_weights` | 使用者、日期、體重、是否空腹 |
| `body_scans` | 使用者、日期，以及 Boditrax 全部欄位（含 10 個分段數據） |
| `jump_tests` | 使用者、日期、站立摸高、助跑摸高、備註 |
| `user_settings` | 使用者、站立摸高、目標值、每週組數目標、循環順序 |

內建動作庫放在程式碼裡（`shared/exercises.ts`），每個動作有固定代碼，這樣之後改版和補動作都不需要動資料庫。

### 5.6 基準資料匯入

寫一個只會執行一次的匯入程式，把 2026-08-02 的 Boditrax 掃描和 2026-09-29 的摸高 305 cm 匯入你的帳號，並記錄已完成，重複執行也不會重複匯入。如果需要你先登入一次才能建立帳號，我會在交付時請你先登入。

### 5.7 和 Manus 分析的串接

- 寫一個匯出程式（`scripts/export-for-manus.ts`），直接從資料庫讀出資料，轉成現有 `fitness-tracker/data/*.csv` 的格式，這樣我原本的 Python 分析和圖表可以繼續用
- 你跟我說「週報」或「幫我看一下」時，我就執行匯出、跑分析，然後給建議

### 5.8 專案結構

## 7. 假設與風險

| 項目 | 說明 |
|---|---|
| 站立摸高 | 用身高 × 1.33 估算為 238 cm，跳躍高度只是推估；之後有實測值，在設定裡改掉即可 |
| Boditrax 輸入 | 掃描大約每 4 週一次，欄位多，需要輸入數字；也可以直接傳照片給我代為輸入 |
| 首次開啟速度 | 閒置後第一次打開可能要等幾秒 |
| 網路 | 健身房訊號差時，記錄會先暫存在手機，結束訓練時才需要網路；如果上傳失敗，會保留資料並讓你重試 |
| 發布 | 完成後會發布成正式網址，這樣才能加到主畫面長期使用 |
